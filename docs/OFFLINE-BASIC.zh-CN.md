# Insomnia 精简离线基础版

本版本面向受控内网的本地 API 调试。默认大陆简体中文（zh-CN），保留用户主动选择的英语。无需 Insomnia 厂商账号，不启动自动更新、云同步、统计上报或在线插件安装。保留原生 TLS 校验、Chromium 沙箱和插件隔离；应用策略不是操作系统防火墙或部署现场安全认证。

## 与旧全插件 RC 的区别

基础版不包含 545 个社区插件及其独立 node_modules；只保留经过固定源码和测试验证的加密实现，功能去重。应用集中于 app.asar，国密与 SHA-3 的固定依赖已编译为一个约 81 KiB 的本地文件，许可证和依赖校验值保留。首次启动不下载插件或算法。旧 offline-full-v13.3.0-rc.1 不作为基础版成品，也不会被覆盖重命名。

每个最终包都记录压缩大小、解压大小、普通文件及目录数、最大文件、SHA-256，以及从实际 ZIP/tar.gz 重新解压并逐文件核对所用时间。该时间是在报告标注的构建机上测得，不是对任意磁盘设备的承诺。预算硬上限为压缩 350 MiB、解压 900 MiB、1500 个普通文件和300个目录；争取压缩200 MiB和500个文件以内。Windows 仅删除与保留载荷逐字节一致的测试残留，并验证干净解压目录下安全入口能够重新创建运行载荷。

## 运行

Windows x64：完整解压，使用 Start-Insomnia-Offline.cmd。Linux ARM64：完整解压，以普通桌面用户运行 ./start-insomnia-offline.sh。保留整个目录，不能单独搬走可执行文件。便携数据在旁边的 data/；升级前关闭程序并备份 data/。

Linux 需要兼容的图形运行库、可用 Chromium 沙箱和系统密钥环（例如 GNOME Keyring/Secret Service）。没有可用加密后端时，凭据保存明确失败，不退回明文。不要通过 --no-sandbox、关闭证书校验或启用 basic_text 来绕过错误。系统密钥环保护的凭据不保证直接跨机器搬迁后可解密。

## 中文与语言切换

首次启动默认为简体中文（中国大陆），不依赖操作系统是否英语。主菜单、项目创建、请求编辑、设置及加解密界面的源代码文案使用本地词典。设置中的“界面语言 / Interface language”可切换英语；保存工作后重开程序，使所有页面和原生菜单统一生效。语言资源随包，不使用在线翻译或全页面 DOM 文本替换。

HTTP 方法、技术标识、请求/响应正文、JSON 字段、代码、密钥、用户项目名称保持原样。少量第三方提示、未收录的长说明或不可用云模块文案可能仍为英语；实际源码覆盖记录在 docs/OFFLINE-LOCALIZATION-COVERAGE.json，不以 HTML lang 参数冒充完整翻译。

## 统一加解密工作台

点击“加解密工具”。所有输入、密钥和结果仅用于当前本地操作；关闭窗口清空表单内容，不上传、不写入使用日志。结果可能含明文或私钥，请自行妥善保存。

- AES-128/192/256：GCM、CBC、CTR；自动安全生成 IV/nonce，可输入指定 IV；GCM 支持 AAD 和认证标签，错误标签或密钥不能返回部分明文。CBC 支持 PKCS#7 或无填充。
- RSA-OAEP：SHA-256/384/512 的小消息加解密；大正文应采用对称加密。RSA、PSS、ECDSA、Ed25519 数字签名与验签，支持相应 PEM/DER/JWK 密钥输入，校验密钥类型和用途。
- JWT/JWS：HS256/384/512、RS256/384/512、PS256/384/512、ES256/384/512、EdDSA 签名与验签；解析和验签分开，拒绝 none/算法密钥混淆，校验适用的 exp、nbf、iss、aud。仅解析结果不能用于身份认证。
- 国密：SM2 加解密、签名验签和密钥生成；SM3 摘要/HMAC；SM4-CBC/CTR。使用随包固定实现，不依赖 Electron/OpenSSL 是否提供国密算法。
- SHA-2/SHA-3 摘要、HMAC、UTF-8/Hex/Base64/Base64URL 转换、安全随机数和密钥生成。MD5/SHA-1 仅为显式旧接口兼容，不称为可解密算法或安全认证方案。

SM2 使用十六进制密钥：私钥64位hex；公钥为带04前缀的未压缩点或支持的压缩点。密文带04点前缀，支持 C1C3C2 / C1C2C3；签名支持 DER 或64字节raw格式，SM3摘要绑定 UTF-8 用户标识（默认1234567812345678）。SM2 当前不接受 PEM/JWK 或 ASN.1 加密密文封装，须先显式转换；不把这些格式混为已支持。SM2 加密拒绝空正文，签名支持空正文。

CBC/CTR 本身不提供完整性认证，不能检测全部篡改；新协议优先选择认证加密。不要重复使用 key/nonce 组合。密钥和算法符合接口规范仍不等于完成独立密码学审计或合规认证。

## 请求和响应联动

保留审核后的 Crypto 请求前 AES-CBC 加密、响应后解密钩子和历史标签兼容性。统一 offlineCrypto 模板标签复用同一工作台核心，不重复安装功能插件。钩子加密失败会拒绝执行，不仅弹窗后继续明文发送。不同协议的签名字段、正文封装、密钥来源必须由用户明确配置；不会把所有请求默认自动加密。

## MQTT 与 OPC

MQTT、OPC UA 属于用户希望具备的可选工业协议能力，当前基础版未集成，也不会显示为已支持。未来独立客户端模块应固定依赖、离线导入、只在明确连接后访问配置目标；不携带完整服务端或另一套 Electron。OPC Classic DA/DCOM 与 OPC UA 不同，不能把 Windows COM 能力宣称为 Linux ARM64 原生支持。
