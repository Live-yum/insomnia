# 精简离线基础版：交付范围与验收标准

更新日期：2026-09-25。用户最新要求优先于旧的“预置全目录插件”目标。

## 最终交付方向

默认交付 Windows x64 和 Linux ARM64 的精简基础版：保留 API 调试能力、补齐基础加解密、按功能去重、显著减少文件数量，并以大陆简体中文（zh-CN）作为首次启动的界面语言。MQTT、OPC UA 是优先评估的可选工业协议模块，不能拖大基础版。

`offline-full-v13.3.0-rc.1` 是历史全目录预览版，不是这一新要求的合格成品。保留它的标签和原始校验值，不覆盖旧资产。本文件也不是“新包已经完成”的声明。

## 去重和体积

不再随基础版分发 545 个社区插件及每个插件各自的 node_modules，不是仅将其默认禁用。没有新的差异化能力的插件不进入包。重复 Hash、HMAC、JWT 解析、编码、主题等优先复用已有能力。旧工作区标签名可以作为同一实现的兼容别名，不再为一个名称复制一套依赖。

当前保留的两个审核模块职责不同：Crypto 提供请求/响应正文 AES-CBC 钩子；Offline Crypto Tools 提供 AES-GCM、RSA-OAEP、HMAC 模板及明确标注“未验签”的 JWT 查看。两者没有 npm 运行时依赖。后续用统一的加解密入口呈现能力，不用插件数量作为完整性指标。

`electron-builder.basic.cjs` 是新的精简打包配置：沿用 Chromium sandbox、原生 libcurl 的解包需求和现有 app.asar；不复制完整插件目录；已静态打入应用的审核插件仅将许可证/来源声明另存于 app.asar 内，不额外复制源码和测试树。保留第三方许可证、安全证书资源、必要 native/WASM 依赖，不能为减包破坏启动、脚本沙箱或 TLS。

新增工程预算（不是实测结果）：压缩包争取不超过 200 MiB，硬上限 350 MiB；解压后总大小不超过 900 MiB；普通文件争取不超过 500 个，硬上限 1500 个；目录不超过 300 个。预算失败须报告最大体积来源，不能静默提高上限或改用更高压缩率掩盖散文件问题。源码仓库保留的历史归档不进入最终软件包。

构建目录检查：`node scripts/offline/basic-budget.cjs directory <解包输出目录>`。
最终归档检查：`node scripts/offline/basic-budget.cjs archive <便携归档路径>`。

实际发布须记录每个平台的压缩大小、解压大小、普通文件/目录/符号链接数、最大体积来源和从最终下载归档解压的耗时。耗时同时记录 OS、工具版本与磁盘环境，不承诺脱离设备条件的固定秒数。ASAR 减少散文件，不等于压缩，也不是安全沙箱。

## 基础加解密矩阵

以下是交付验收范围，不代表当前版本均已实现：

| 能力 | 范围与要求 |
| --- | --- |
| 对称加解密 | AES-128/192/256 的 GCM/CBC/CTR；明确 key/IV/nonce/tag/AAD、填充和 UTF-8/Hex/Base64 编码，不能只支持私有封装格式。 |
| 非对称与签名 | RSA-OAEP 加解密，RSA-SHA256/RSASSA-PSS、ECDSA/Ed25519 常用签名验签；PEM/DER/JWK 输入与公私钥用途校验。大正文采用对称加密，不伪装成 RSA 可任意长度加密。 |
| 摘要和 MAC | SHA-2/SHA-3、HMAC；MD5/SHA-1 只标注为旧接口兼容，不能称作可解密算法。复用现有实现。 |
| JWT/JWS | 解析和验签明确分开；为所声明的 HS/RS/PS/ES/EdDSA 算法提供实际签名验签，算法白名单与 key 类型绑定；校验 exp/nbf/iss/aud；拒绝 none 和密钥混淆。 |
| 国密 | SM2 加解密/签名验签、SM3、SM4；必须有独立已知答案与跨实现互通测试，不能以 OpenSSL 有算法名称或自写未审计算法冒充完成。 |
| 工具与联动 | Hex/Base64/Base64URL/URL 编码转换、安全随机数/密钥生成、请求前加密签名及响应后解密。新加密使用新鲜 nonce/IV；密钥遮蔽且不写日志。 |
| 旧算法 | DES/3DES、ECB 等仅作为旧接口确有需求时的显式兼容选项，明显警告且非默认；不能偷偷启用 legacy provider 或关闭验证。 |

每项记录唯一提供者、实现版本、测试向量、Unicode/空输入/编码边界、错密钥/篡改/错误填充/错误签名、重启和打包后执行结果。失败必须报错，不能返回半段明文或退回未加密发送。当前 crypto.test.cjs 的通过不代表上表全部完成。

## MQTT 与 OPC

MQTT 优先支持 3.1.1/5.0、TCP/TLS、WebSocket/WSS、连接/断开、发布/订阅、QoS 0/1/2、retain、遗嘱、用户名密码、客户端证书和自定义 CA。只在用户明确连接后访问目标，不自动连公共 broker；验证失败不能关闭 TLS。仅安装 npm mqtt 包或仅支持浏览器 WebSocket，不算原生 MQTT 完成。

OPC 默认按 OPC UA 规划：端点连接、证书信任、节点浏览、读取、订阅、明确确认后的写入与方法调用。只带客户端依赖，不把完整服务器、全部工业节点集和第二套 Electron/Node 运行时放进基础版。默认不自动写入设备，不自动接受未知服务器证书。

OPC DA/AE/HDA（Classic）依赖 Windows COM/DCOM，与 OPC UA 不同。Linux ARM64 不宣称原生支持 OPC DA。Classic 需要单独评估 Windows 模块或可信内网网关。

扩展复用应用运行时、固定依赖和校验清单，可离线导入；不能要求进入内网后 npm install，也不能通过放开任意插件权限实现协议支持。没有完成的协议实现不出现在“已支持”列表。

技术依据：https://github.com/mqttjs/MQTT.js 、https://github.com/node-opcua/node-opcua 、https://opcfoundation.org/about/opc-technologies/opc-classic/ 。版本锁定和客户端最小依赖评审在集成时进行。

## 大陆简体中文

首次启动默认 zh-CN，不依赖系统语言；用户主动切换英语后保存选择，升级不覆盖已有选择。实际翻译菜单、请求编辑器、加解密工具、设置、验证错误和帮助。HTTP 方法、JSON 属性、用户请求/响应正文、模板标识符、代码和密钥不翻译。

语言资源全部随包。不要在线翻译，不用 MutationObserver 全页面替换文本；不能仅设置 Electron --lang、HTML lang、README 或包元数据后称为中文界面已完成。原生语言配置与应用字符串翻译分别验收。在英文系统的干净配置上验证中文 UI、加解密错误提示、语言选择持久化、输入法和布局。
